### 1.3 官方文档中的要点

- **Arduino 开发板选择**：`ESP32S3 Dev Module`。
- **原生 USB 用作 `Serial`**：必须把 `USB CDC On Boot` 设为 `Enabled`。
- **一根 Type-C 线在电脑上出现两个 COM 口**：一个是原生 USB，用于烧录和 CDC/HID 等 USB 设备功能；另一个是 CH343，用于烧录和查看 `Serial0` 日志。
- **怎么区分两个口**：按一下 RESET，**消失后又重新出现**的那个就是原生 USB 口。

### 1.4 乐鑫文档中的要点

- GPIO0、3、45、46 是启动配置脚（strapping pin）。
- 使用 Octal PSRAM 时，GPIO33–37 被占用，不建议他用。
- GPIO19、20 默认用于 USB-JTAG。

## 3. 旧云台控制板协议（原 RV1126B 驱动；**电机本身不认**，仅供参考）

FZYT-28 就是原 on-device 自研云台的电机，原来接在 RV1126B 的 UART7 上（3.3V TTL 直连）。控制协议来自 RV1126B 的 ODM 固件镜像（`标准语音板/firmware/update-dr4-rv1126b-buildroot--20260811-154525.img`）中的 `librp_mw.so`，对 `RpMwPtzControl*` 系列函数做了反汇编：

- **初始化**：`rp_mw_uart_open(dev, 115200, 8, 'N', 1)`，然后发一帧 MasterOn
- **每条指令**：从 `.rodata` 偏移 0xa570 的表中取 5 字节，第 6 字节为前 5 字节的累加和（sum8），一次写入 6 字节
- **停止**：驱动记录上下、左右两轴是否在转，只给正在转的轴发停止帧
- **关闭**（DeInit）：发一帧 MasterOff
- **接收**：不读取任何数据
- **串口参数**：115200，8N1
- **帧格式**：6 字节，`FC 80 <b2> <b3> 00 <sum8>`
- **背景文档**：`on-device-algorithms/docs/hardware-knowledge/gimbal-uart7-custom.md`（该文档没有帧字节，下表是反汇编补出来的）

| 指令 | 帧 | 指令 | 帧 |
|---|---|---|---|
| Up | `FC 80 01 00 00 7D` | Reset | `FC 80 11 06 00 93` |
| Down | `FC 80 01 01 00 7E` | MasterOn | `FC 80 11 09 00 96` |
| Left | `FC 80 10 02 00 8E` | MasterOff | `FC 80 11 0A 00 97` |
| Right | `FC 80 10 03 00 8F` | AiFollowOn | `FC 80 10 04 00 90` |
| 停止上下 | `FC 80 11 07 00 94` | AiFollowOff | `FC 80 11 05 00 92` |
| 停止左右 | `FC 80 11 08 00 95` | PrivacyOn / Off | `FC 80 11 0B 00 98` / `FC 80 11 0C 00 99` |

**推测**（待真机验证）：第 3 字节是电机 ID，`0x01` = 俯仰，`0x10` = 水平，`0x11` = 全部。依据是规格书写了"多 ID 串口控制"，而且上下、左右两组指令正好用了不同的值。

**2026-09-18 实测结论**：FZYT-28 电机对这套帧完全不响应。这套协议是发给原云台里另一块控制板的，电机的真实协议见第 4 节。

## 4. 电机实际协议（2026-09-18 真机实测）

**方法**：电机 TX 接 ESP32 GPIO18 后，用飞特/Dynamixel/幻尔三家的 PING 帧在 9 个波特率下轮流探测，只有 **1,000,000 波特率 + 飞特格式广播 PING** 得到应答 `FF F5 02 02 00 FB`（ID 2，错误码 0，校验正确）。随后读写寄存器验证，并完成 90° 往返移动。

| 项 | 实测值 |
|---|---|
| 帧格式 | 飞特 SCS 系列：`FF FF ID LEN INSTR PARAM… CHK`，`CHK = ~(ID+LEN+INSTR+PARAM…)` |
| 应答 | `FF F5 ID LEN ERR DATA… CHK`（第二个头字节固定 F5）；**写指令无应答** |
| 波特率 | **1,000,000**，8N1 |
| 字节序 | 16 位寄存器**大端** |
| 出厂 ID | 2（两个电机都是） |
| 位置分辨率 | 4096 计数 = 一圈 |

**已验证的寄存器**：

| 地址 | 含义 | 出厂值 | 备注 |
|---|---|---|---|
| 0x00 | 固件 | 0xAA55 | |
| 0x03 | 型号 | 0x4121 | |
| 0x05 | ID | 2 | |
| 0x06 | 波特率码 | 2 | 对应 1 Mbps |
| 0x09 / 0x0B | 最小 / 最大角度限位 | 0 / 4095 | |
| 0x0D | 最高温度 | 50 | 单位 °C（推测） |
| 0x0E / 0x0F | 最高 / 最低电压 | 10 / 4 | 单位 V，与规格书 5–10V 对应 |
| 0x15 | 位置环 P | 77 | 实测改成 20 后到位晃动反而变大，已恢复 77 |
| **0x16–0x17** | **零位记录（2 字节）** | 8 | ⚠ **不是飞特表的 D**。写入任意值 → 电机把当前位置记进来。2026-09-18 误写过一次，现值 720；**电机断电重启后 0x38 读数不变（仍 719）**，即该寄存器目前不影响位置读数，只是记录。真实用途待厂家确认 |
| 0x21 | 模式 | 0 | 位置模式 |
| 0x28 | 扭矩使能 | **0** | 写 1 才会动 |
| 0x2A | 目标位置 | 0 | 写入后立即全速运动 |
| 0x2C | （飞特表为运动时间） | 0 | 能写能读，但对速度无作用 |
| 0x2E | （飞特表为目标速度） | 0 | **写入无效** |
| 0x38 | 当前位置 | — | 到位后有 ±40 计数抖动 |
| 0x3A | 当前速度 | 0 | |
| 0x3E / 0x3F | 电压 / 温度 | 0 | 读得到但恒为 0 |
| 0x3C / 0x42 / 0x45 | 负载 / 运动标志 / 电流 | — | **无应答**，此表没有这些地址 |

**旁证**：规格书功能列表（绝对位置、多圈、零位、软限位、PID、扭矩关闭、过载保护、多 ID）与飞特 STS/SCS 系列的寄存器功能一一对应。

**到位精度实测**：±45° 移动 0.3 秒内到位，稳定后偏差 0–1 计数，静止时读数不抖。早先观察到的到位后 ±30 计数低频晃动是间歇性的，怀疑与电机本体未固定有关，待确认。

**探测时的一个坑**：电机上电/断电瞬间 TX 会抖一下，230400 以上的波特率会把它收成单个 `FF`/`FE` 字节，容易误判成"电机在发数据"。固件的 `scan` 已排除这类单字节毛刺。
